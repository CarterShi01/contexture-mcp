# 路线图

[English](roadmap.md) · [文档导航](README.zh-CN.md) · [设计](design.zh-CN.md)

Contexture 的下一步建立在职责导向结构与显式能力图之上：让面向 Agent 的应用
更容易理解、评估和演进。以下是**计划方向，不是已交付功能或发布日期承诺**，
具体范围应由实际应用需求驱动。

## 1. 面向应用代码的人与 Agent 意图对齐

随着 Agent 参与构建和修改应用代码，人的理解与审查可能成为瓶颈。我们计划提供
能力图可视化和披露过程演示，将开发者预期的职责、关系与 Agent 接收的上下文、
使用的能力连接起来。

现有基础是编译后的能力图，以及 `check`、`list`、`inspect` 命令。
一个有用的起点是直接呈现真实结构和披露内容，而不是另外维护一套模型。
图形展示可以帮助审查结构，但不能证明人与 Agent 在语义上完全理解一致。

## 2. 能力级评估与调试

代码正确不等于 Agent 行为可靠。模型、描述、指令或应用结构的变化都可能影响
结果。我们计划围绕能力节点和导航路径进行评估与调试，利用明确的职责边界定位
失败，并改进描述、Skill 指令和图的组织方式。

已有图检查和运行时测试覆盖结构及执行契约，不替代任务级评估。
未来诊断应依据可观察的工具调用、披露上下文和任务结果，与端到端测试及回归
检查配合，而不是把图合法等同于任务成功，也不假设能够访问模型的隐藏推理。

## 保持同一基础

目标是让能力图同时支持应用设计、人的理解和评估驱动的改进，不需要因此增加
新的 Agent 循环，也不把业务授权迁入 Contexture。

有用的反馈包括应用任务、相关能力结构、难以理解或调试的地方，以及可观察的
预期结果。可以通过 [Issue](https://github.com/CarterShi01/contexture-mcp/issues)
分享脱敏示例，不包含凭据或私有数据。发布流程与历史准备状态分别保留在
[项目状态](project-status.md)和[发布指南](../RELEASING.md)中。
